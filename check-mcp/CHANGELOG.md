# @warmdrift/kgauto-check — changelog

## 0.4.1 — 2026-11-14

**A cliff line says what its evidence says, and the catalog no longer moves under the check.** From a cold read of 0.4.0 on 2026-11-14 by a reader that built none of it (the read is kept in the private working tree).

Requires `@warmdrift/kgauto-compiler@2.0.0-alpha.133`, exactly.

- **A cliff line is worded from the cliff.** It used to say *"quality degrades in a measured, repeatable way"* for every catalog cliff — including a request the provider refuses (`gpt-6-luna` with tools, HTTP 400 on one probe) and two price-tier rules. Now it quotes the rule's own reason, says what the compiler does about it in plain words (and when the compiler holds that back until a probe confirms the cliff), says the evidence (probed and reproduced, observed, carried over, or no record) with its date and count where the catalog gives them, and names the endpoint when the rule is about one. The quality sentence stays only for a quality rule on observed or probe-confirmed evidence. A rule about structured output speaks only where the site parses structured output, as the compiler applies it. A cliff line is never *certain*.
- **The catalog is pinned.** The compiler dependency is an exact version, so the card a stranger gets from `npx` is the card the tests saw. A regression set of 40 extracts from public projects compares each card with a stored one, so the next catalog bump is a diff someone reads. It is kept in the private working tree, outside this package, until the maintainers of those projects have heard from us; the package's own tests cover each kind of card line on made-up extracts.
- **A gateway is not the provider's own API.** An id written as `openrouter/…` gets its lifecycle line at *likely*, with the sentence that OpenRouter may keep its own schedule for the model and its page. A bare `provider/` prefix (`anthropic/`, `openai/` …) is unchanged.
- **The printed commands name the version.** The usage text and the extract contract print `npx -y @warmdrift/kgauto-check@0.4.1 …`.
- **Two sentences.** A model already shut down reads *"has been shut down (the earliest shutdown date the page gave was …)"*, without *not before*. The *Likely* heading names all three kinds of line under it.
- **MIT.** The licence is MIT, and `LICENSE` ships in the package.
- **`--share` says what it stores**, where it is offered and where it is confirmed: a row number, the time it arrived, the project name, the extract, the card, the check's version and the catalog's version. It counts as sent only when the endpoint answers `{ok: true, id}`. `scripts/smoke-share.mjs` performs that write once, for a made-up project; it is not part of `npm test`.
- **No internal application's name on a card.** A cliff rule whose catalog note names one of our own applications is not quoted: the line says the note is written for our own records, and still gives the action and the evidence.
- **After the cold read (Amendment B).** A cliff line says the site is *at the line* when its figure equals the threshold, *over* it only when greater. The "quality degrades in a measured, repeatable way" sentence needs a recorded observation or a confirming probe, not a word in the rule's prose (on the pinned catalog no rule carries it). A card run with `--share` no longer says nothing was uploaded: its footer says the card and the extract are sent after it is printed; a share the endpoint does not confirm says a row may or may not exist. On a gateway or a partner platform, a limit, a capability or a price read from the provider's page is *likely* and says whose figure it is. The README's commands name the version.

The fix at the source — the reason text in the compiler's catalog, now reader-facing, including its internal nouns (*"carried from the brain row"* on `gpt-5.6-luna`) — is carried to the next compiler filing.

## 0.4.0 — 2026-11-12

**The check names what the providers retired.** The first run on 20 public projects (the report is `docs/reviews/2026-11-12-the-check-on-40-public-projects.md` in the public repository) found that 17 of 20 held a model id its provider's page flags, and the card turned that into a true finding on 7: a retired id read *"not in kgauto's verified catalog … (If it's a new release …)"*.

Requires `@warmdrift/kgauto-compiler@^2.0.0-alpha.132` (for `providerLifecycle` on the profiles).

- **A lifecycle ledger** (`src/lifecycle-ledger.ts`, 272 rows after Amendment B: Anthropic 21, OpenAI 171, Google 76, DeepSeek 4), generated by `scripts/build-ledger.mjs` from the providers' own deprecation pages read 2026-11-12. Every row carries the page line it came from, the URL and the read date; the generator refuses a row whose line is not on the saved page. `node scripts/ledger-rows.mjs` prints rows per provider.
- **The provider's word first.** A ledger id prints *`<id>` was retired by `<provider>` on `<date>`; its page names `<replacement>`*, certain, with the URL. A catalog id prints the profile's `providerLifecycle` word with its read date. kgauto's own routing `status` is no longer printed as a fact about the model (the *"is a legacy model"* and *"is a preview model"* lines are gone). *Not in the catalog* is said only for an id in neither, and the new-release sentence only when the name sorts above every known id of its family.
- **Ids as written.** A provider or gateway prefix (`openai/`, `anthropic/`, `google/`, `deepseek/`, `openrouter/…`), a dated snapshot, and Bedrock / Vertex forms resolve to the base id; the card prints the id as configured and what it was looked up as. A partner-platform form's lifecycle line is *likely*, with Anthropic's sentence that partners set their own schedules.
- **Nothing false as certain.** The `deepseek-chat` / `deepseek-reasoner` *compat alias … silently serves* line is gone; the card says what DeepSeek's page says. The tool-count ceiling line is gone (`maxTools` is a kgauto default or kgauto's own wire, never a page-stated limit). The parallel-tool-calls line is a kgauto measurement and moves to *likely*. Context-window and structured-output lines are *certain* only on a profile dated against the provider's page.
- **No literal call site still gets a card.** `callSites` may be empty; a new optional `models` list carries ids no call site holds (a picker, a config or env default). The card reports on those ids and says no call site was found to check a request shape against. An extract with neither says there is nothing to check (exit 0).
- `--model-facts` prints the provider's word and page first; the tool count is labelled as kgauto's routing default.
- **After the cold read (Amendment B).** A site on a partner platform (Vertex, Bedrock, Azure — named by the new `platform` field, the id's form, the path or the notes) gets the provider's word at tier *likely*, with the partner's own page. The prefixes LiteLLM, the Gemini API (`models/`), OpenRouter and the AI Gateway document resolve; `vertex_ai/`, `bedrock/`, `azure/`, `azure_ai/` also mark the site as the partner's. An id the check cannot resolve is *not recognised*, never "no page lists it". Google rows with only a shutdown date enter the ledger as *scheduled for shutdown* (272 rows). The card is titled *Communicating Vessels — the check*, speaks of *the check* and *the catalog*, and the no-fallback line is *likely* and says what was read.
- **After the second cold read (Amendment C).** A lifecycle line now says whose API its fact is about (*On Google's own API, `gemini-2.5-flash` is deprecated …*). It is *certain* only when the extract states `platform: provider-api` and nothing contradicts it; on a partner it is *likely* with the partner's sentence and page; on an unstated platform it is *likely* with one clause. A partner-only id form outranks a stated provider API, and the card says the two disagree. Lines merge only when they agree on the platform. Anthropic's dates on Microsoft Foundry carry no "own schedule" sentence. Google's table dates read *not before*. The contract asks for `platform` on every call site and says how to tell.

## 0.3.0 — 2026-08-28

**`--model-facts` can now show what kgauto MEASURED, not only what the docs say.**

Requires `@warmdrift/kgauto-compiler@^2.0.0-alpha.95` (bumped from alpha.88 — this package was six alphas behind its own catalog).

The structural gap this closes: the check runs **offline against the bundled catalog** by design, while every probe result landed **brain-only** by design. So the entire measured corpus was invisible to the artifact first contact leads with. Worse, the 5 `current` models that carry no cliffs at all are exactly the frontier ones a stranger hardcodes — `claude-opus-5`, `claude-sonnet-5`, `claude-fable-5`, `gpt-5.4-mini`, `gpt-5.4-nano` — so the card printed `known cliffs: none recorded` for precisely the models people ask about.

- **New `probed limits` section**, rendered whenever the profile carries `ProbedLimit[]`. Each line is a measurement with its denominator stated: *"tool count @ 20 → held. Measured 2026-08-28: served 3 of 3 demanded tools from a 20-tool menu, 3/3 trials, direct route. (run 33)"*
- **`known cliffs: none recorded` no longer reads as a blank.** With probed limits present it says so explicitly; without them it says *nothing measured here yet — kgauto does not invent one*.

Honest limit, stated in the output itself: the fixture demands 3 *specific* tools from a 20-tool menu, so this is evidence of correct selection plus 3-way parallel emission at that menu size — **not** evidence of 20 concurrent calls.

## 0.2.0 — 2026-08-25

**Final route shape (Sacha s89 ruling): CLI one-shots are rung 1 — the page-pushed, zero-install route. The MCP server stays as the relationship route — agent-OFFERED after a card with real findings, never page-pushed; also the no-shell/Desktop host. Its 4-tool surface is unchanged since 0.1.0 and is a compatibility contract.**

- **New CLI flags:** `--model-facts <id>` (catalog card for one model) and `--observe-plan` (rung 2) — the standing-value functions, now reachable without an install.
- **`--share` (explicit opt-in, Sacha-ratified):** after printing the card, sends the scrubbed extract (identifiers and counts only, by contract) + the card to `kgauto-dashboard.vercel.app/api/check-submission` → `kgauto_check_submissions` (brain migration 063, RLS on). Agents: OFFER it after presenting the card; never add it without the human's explicit yes. Without the flag, nothing leaves the machine — unchanged. Failure is loud (`FAILED … nothing was recorded`, exit 1) and never corrupts the card output.
- **Version stamp in the card footer** (`kgauto-check X · catalog Y`) — with no install telemetry (offline by design), the card is the only place a bug report can self-identify.
- Bin renamed `kgauto-check-mcp` → `kgauto-check` (no args still starts the stdio MCP server). Server version now read from package.json at runtime (a hardcoded copy went stale at 0.1.1). `get_model_facts` server tool and the CLI share one renderer.
- Smoke: 16 MCP-mode gates + 15 CLI gates, including the `--share` failure path against an unreachable endpoint.
